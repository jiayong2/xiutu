# 战斗 UI 与动画优化验收记录（2026-11-05）

本轮以用户补充修订为准：法术直接生效，取消附件旧版提出的矩形弹丸、飞行物、移动轨迹及不同元素专属动画。普通攻击保留前冲与返回。没有新增正式游戏内容、改动属性/伤害公式/概率/速度顺序/奖励规则。

## 实现及复用

- 复用 BattleSystem.action 原有整轮结算，在每个真实行动前后提取 HP、MP、状态、行动者、行动种类及真实暴击标记。原来随机调用和行动判定位置不变；没有让动画调用伤害计算。
- 主页面提交一次原 battle_action，事务和奖励立即完成，再向原 BattlePage 传入只读事件。播放期间禁止重复提交；结束后绑定最终数据，继续复用原结算弹窗与报告。
- 原生 Tween 队列：顶部头像间距、移至右侧行动位、当前单位高亮；双方普通攻击前冲/返回、受击轻退/闪红/数值飘字。
- 全部已有法术共用名称提示、目标反馈和 HP/MP Tween。治疗闪绿、恢复数值；护体/灼烧/潮湿显示实际名称并刷新已有状态栏。施法者不前冲，只有普通攻击分支移动单位。
- 多目标反馈按事件中实际变化的目标遍历；没有增加群体战斗规则。没有 HP 变化的目标不闪红，也不制造命中数字。
- 使用同一 battle_page.tscn 模板，保留用户既有布局、Source Han 字体、纯色单位占位。没有生成美术资源、投射物节点、粒子或 Shader。
- 支持表现倍速 1/1.5/2 和跳过动画；不改变 TimeSystem、随机状态及奖励。切换页面先停止 Tween 并完成队列清理，再释放原界面，避免悬挂的动画等待对象。动画后恢复道具、展开和其他可用按钮。
- 日志增加实际行动、伤害/恢复、状态回合，使用原 battle.log。玩家向上阅读历史时保留滚动位置。

## 修改文件清单

1. gameplay/battle/battle_system.gd：真实行动展示事件与详细日志。
2. ui/battle/battle_page.gd：共用 Tween 表现、稳定单位节点、清理及防重展示。
3. ui/battle/battle_page.tscn：行动轨道及跳过按钮，可直接编辑预览。
4. ui/main/main.gd：请求/表现衔接和页面切换清理。
5. tests/battle_animation_preview.gd（及 Godot 生成 uid）：专项实际页面测试。
6. docs/ui_battle_animation_review.md、decisions.md、development_plan.md、data_schema.md：本轮技术与验收记录。
7. docs/screenshots/battle_attack_motion.png、battle_skill_*_instant.png、battle_animation_small.png：Godot 运行截图（非美术资产）。

## 验证

Godot 4.5 stable Mono / OpenGL 实际运行：

- 动画专项：144 检查，0 失败。覆盖攻击、五种原有法术、道具、防御、胜败/逃跑、跳过、二倍速、页面中断、多次进入、滚动历史和窗口大小；逐项对照同一状态及同一随机流下无动画请求的完整存档结果，动画前后状态不变。
- 多目标采用明确隔离的 UI 测试快照，不修改正式群体玩法；验证两个受影响目标均反馈、未受影响施法者无受击反馈。
- 原战斗页面：357 检查，0 失败；原结算页面：42 检查，0 失败。
- tests/run_all.ps1：配置、导入、核心、玩法、回归、边界、任务及无头启动全部通过。未降低现有断言。
- 检查 1920×1080 和 1280×720 实际截图，名称、治疗数值分层排列。检查期间发现并修复切页悬挂等待对象及动画后道具/展开未恢复；最终专项无脚本错误及对象泄漏警告。

## 边界与遗留

- 正式玩法仍为既有单人对单怪。多目标展示能力仅验证接口；不冒充已实现多人/群体法术业务。
- 现有战斗计算没有闪避、免疫、抵抗结果类型。本轮没有虚构这些规则和提示；只根据真实 HP/状态变化反馈。未来增加这些机制时须由战斗系统输出真实结果，表现层不得推测命中。
- 自动战斗底层尚未实现，原入口继续明确禁用，不为动画任务新增玩法。
- 可选的生命条拖影没有新增；原生命、灵气和状态已使用 Tween。
- docs/game_design.md、docs/content_v0_1.md、docs/combat_balance.md 不存在，沿用已存在的中文设计/内容文档、data_schema、阶段计划及决策记录。工作目录未初始化 Git，未执行提交。

验收：用户本轮修订及既有已支持战斗范围 PASS。附件中依赖未开发自动/多人机制的完整远期范围仍为 PARTIAL。下一步建议用户实际体验动画节奏和字号；不自动推进玩法开发。
