# 行动顺序条 V2.0 与飘字调整验收（2026-11-05）

## 范围与依据

按用户本轮明确布局执行：紧凑靠左，先行动靠右，最右为当前行动位，固定“◀ 行动中”指示。保留既有固定回合规则，不开发集气、自动战斗或多人战斗业务。

已阅读 AGENTS.md、development_plan、decisions、data_schema、现有战斗/操作/页面及测试；战斗规则沿用《仙途_V0.1_最小可玩版本_商业开发实施文档.md》与《仙途开发文档.md》。game_design.md、content_v0_1.md、combat_balance.md 仍不存在，未把缺失文档视为重新设计授权。当前目录未初始化 Git，无法提供 Git diff，未执行提交或重置。

## 实现

- 新增可复用 turn_order_bar 和 turn_portrait 原生场景/脚本。主 battle_page.tscn 实例化同一模板；编辑器可直接预览紧凑轨道和指示文字。头像位置位于独立 Control/Panel 层，避免容器排版覆盖 Tween。
- 头像 48×48，间距 16，轨道高 72，左右 padding 16，宽度 clamp(32+n×48+(n−1)×16,200,650)。例如双人 200、四人 272、六人 400。指示文字位于轨道右侧 12px，同步跟随宽度变化，保持相对位置固定。
- 保留单位 ID 对应的头像对象，下一位从右侧进入当前行动位，其余头像用 0.5 秒缓入缓出 Tween 同时移动。金色边框只在布局完成后切换，与场景绿色行动高亮通过同一 current_changed 信号同步。
- 本轮未行动者按真实行动事件顺序排列；已经行动者依照原下一轮顺序进入队尾并标注“下轮”。此标记只显示，不增加行动次数。每轮结束复原下一轮真实队列。
- 阵亡或离场头像淡出并移除、宽度平滑缩短；加入及外部队列更新同样平滑适配。新状态到来时杀掉旧布局 Tween，从当前实际位置向最新目标移动，清理中断的离场节点，避免重影与重复 ID。
- 超过 9 人时轨道固定 650，保留完整队列，仅展示当前及接下来 9 位；“全部”按钮查看完整 ID 对应顺序，未删除真实队列信息。
- 原流程缺少公共队列查询，因此仅提取原 stats.speed>=enemy.speed 判断为 BattleSystem.action_order。原执行循环和 UI 共用这一只读方法；伤害、随机、结算、回合边界均不变。UI 不再自行按速度/阵营排序。通用组件只接受调用方给出的先后 ID 数组。
- 伤害及暴击伤害统一红色 42 号字，从矩形正中心上浮。治疗仍为绿色。行动中、法术名和特殊攻击为水平居中的 32 号字。原 .65 秒反馈延长至 1.6 秒（前 1.05 秒保持可读，再淡出），战斗倍速仅影响表现时间。
- 状态名在真实施加/刷新时显示，与伤害数字分层；自然减少剩余回合只更新原状态 UI，不反复叠出名称。没有飞行物、轨迹、粒子、Shader、贴图或音效。

## 验收边界

本轮 UI 表现范围 PASS。多人测试为明确隔离的 4/6/12 人 UI 队列，不代表新增正式多人战斗业务；正式内容仍原单人对单怪。原系统没有自动战斗，本轮仅验证快速连续更新和表现倍速，不伪称自动玩法已接通。存档结构没有变化。

下一步建议在实际游玩中确认紧凑度、0.5 秒移动与 1.6 秒文字时长，等待用户反馈，不自动推进其他系统。
