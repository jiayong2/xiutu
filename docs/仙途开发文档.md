# 《墨色仙途》游戏设计与开发规范 V1.5
整合修订版 · Godot 4.x

> 当前开发以本文、[内容文档](仙途_V0.1_最小可玩版本_商业开发实施文档.md)和[已批准决策](decisions.md)为设计基线。后续批准的地点首页、统一在线时间和任务规则优先于本文对应历史描述。

本文档整合此前确定的动态修仙世界、洞府经营、回合制战斗、任务系统、代码规范、Debug 和开发阶段，并以最新确认的主界面布局为准，替换旧版相互冲突的 UI 设计。

### 核心游戏体验
玩家从一名炼气散修开始，在有限寿元内修炼功法、突破境界、探索秘境、结识 NPC、加入宗门、经营洞府。

玩家闭关期间，世界不会停止发展。NPC 可能突破、死亡、结仇或加入宗门；城镇经济可能发生变化；宗门可能兴盛、衰落或争夺领地。

世界演变不是随机新闻，而是实际改变游戏数据，并对后续玩法产生影响。

## 第二章：全局 UI 设计规范
### 2.1 统一设计原则
1. 所有页面以 1920×1080 为基准。
2. 初期只使用矩形、文字和简单图标。
3. 界面采用上下分区布局，避免大型左中右详情栏。
4. 主界面上部三个大面板占主要空间，下部九宫格按钮压缩。
5. 同类组件统一尺寸、颜色、边距和字体。
6. 所有矩形记录 `X、Y、W、H`。
7. Godot 使用 `Control`、容器和锚点实现布局。
8. UI 不直接修改游戏数据，只通过系统接口发起操作。

## 第五章：洞府系统
洞府初期只有一处固定地点，采用静态俯视图，通过点击设施进入对应页面。

### 洞府设施规范
| 设施 | 首版功能 | 时间规则 |
| --- | --- | --- |
| 修炼室 | 打坐、闭关、突破 | 推进世界时间 |
| 炼丹房 | 丹方、材料、直接结算 | 按丹方推进时间 |
| 灵田 | 固定 4 格，播种、收获 | 随游戏时间生长 |
| 灵阵 | 1 个阵法运行槽 | 按月消耗灵石 |
| 洞府升级 | 扩充设施、解锁功能 | 按升级规则结算 |
| 洞府仓库 | 存入、取出、整理 | 不推进时间 |


灵田初期种植凝露草、青灵草、火灵草、清心叶等。

阵法初期规划聚灵阵、催生阵、护府阵、养元阵。升级洞府后逐步解锁。

所有洞府系统与统一游戏时钟关联。

## 第六章：动态世界
世界初期规划五座城镇、三个宗门。

| 城镇 | 主要功能 |
| --- | --- |
| 青岚镇 | 新手、委托、基础商店 |
| 云溪城 | 炼丹、药材交易 |
| 玄铁城 | 矿石、法宝、锻造 |
| 赤霞坊市 | 功法、特殊交易 |
| 临渊城 | 高阶任务、秘境 |


宗门包括青岳宗、百草谷、赤阳门。

### NPC 行为
重要 NPC 拥有年龄、境界、性格、天赋、财富、所在地点、所属宗门、目标和关系。

NPC 可以修炼、突破、外出探索、交易、迁移、拜师、结仇和死亡。

各地点可用通用配置举办拍卖会。已开放的云溪城场次由世界日期决定入场窗口，竞价按事件推进，成交和冲突可改变 NPC 财力、持有物与关系。设计与验收见 [拍卖和神识专项](auction_review.md)。

### 世界演算
+ 每日：处理短期事件及到期状态。
+ 每月：NPC 成长、商业变化。
+ 每季度：宗门发展和势力冲突。
+ 每年：人口变化、长期事件和统计。

世界采用数据模拟，不加载所有城镇场景。仅在玩家进入某地时实例化所需 UI 和角色表现。

## 第七章：战斗与成长
战斗采用速度排序的回合制，初期不做 ATB。

玩家指令包括普攻、法术、防御、道具、逃跑。

功法是被动效果，法术是主动技能，法宝提供装备加成。

角色主要属性为生命、灵力、攻击、防御、速度、暴击和五行属性。

修炼体系以炼气、筑基、金丹、元婴为初步规划，MVP 优先完成炼气至筑基突破。

法体修炼、根基温养与九阶边界按 [DEC-031 至 DEC-033](decisions.md) 执行。体修有独立境界与进度，法体共用时钟、地点灵气和功法装备规则。正式修炼按吸纳、运转、炼化、损耗与温养分账结算。

寿元采用当前年龄和寿元上限分离的设计。修炼、旅行、炼丹、探索消耗游戏时间，突破后可提高寿元上限。

### 强制代码要求
+ 一个模块负责一个领域。
+ 数据、业务逻辑、UI 分离。
+ 所有 NPC、商品、技能、任务使用唯一 ID。
+ 公共函数定义明确的参数、返回值和错误处理。
+ 复杂操作有日志及操作 ID。
+ 修改世界数据必须经过对应系统。
+ 不允许 UI 自行修改背包、灵石、境界。
+ 所有关键系统支持独立测试。
+ 存档包含数据版本。
+ 每次阶段开发完成后提交 Git 版本。

## 第九章：Debug 规范
开发者使用 F1 打开调试中心。

| 功能 | 说明 |
| --- | --- |
| 玩家调试 | 修改等级、修为、灵石、生命 |
| 背包调试 | 生成、删除指定物品 |
| 战斗调试 | 指定敌人、技能、伤害 |
| NPC 调试 | 查询、修改境界与位置 |
| 世界调试 | 推进月份、触发世界事件 |
| 宗门调试 | 修改资源、成员、关系 |
| 洞府调试 | 灵田成熟、炼丹、阵法 |
| 任务调试 | 接取、进度、完成 |
| 存档调试 | 快照、恢复、结构验证 |
| 日志调试 | 筛选 INFO/WARN/ERROR |

每个 Bug 报告必须记录游戏版本、关联模块、操作 ID、复现步骤、预期结果和实际结果。

动态世界系统必须支持固定随机种子与可重现模拟。

## 第十一章：当前版本确定事项
主界面确定为上下布局。 上方三个大型信息面板，下方三行九宫格按钮。

所有 UI 以 1920×1080 为基准。 使用统一像素坐标和组件尺寸。

洞府统一管理炼丹、灵田、灵阵、升级和仓库。 初期仅一处洞府。

动态世界按游戏时间结算。 后台 NPC 和城镇不需要持续创建画面节点。

代码与 Debug 同步开发。 所有关键功能必须能测试、记录和复现。

V1.5 作为当前整合基线。 旧版主界面的左右大分栏布局、底部单排九按钮布局均不再采用。尚未逐页确定的 UI 仍需按本版上下分区标准补充精确坐标，商店价格、技能倍率、NPC 详细属性等数值也需建立独立数据表后再冻结。
