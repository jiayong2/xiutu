# 任务日志重构与可编辑模板交付

日期：2026-11-05。范围：任务日志重构，以及现有主界面转为可编辑场景；未生成其他页面布局模板。

## 问题与方案

原任务界面把全部描述、状态、接取/提交按钮堆在纵向列表中；没有选中详情、分类或明确的操作区，NPC对话孤立于列表下方。

本次使用32px安全边距、24px区域间距、16px组件间距、48px普通按钮；顶部为“任务”标题与返回，下方四分类；主体使用HBoxContainer按32/68比例分配列表与详情。列表项高96px，只展示名称、类型和状态；详情以名称/类型、描述、目标进度、相关人物地点、奖励的顺序展示。详情正文与任务列表分别滚动；说明与操作按钮固定在详情底部，不随长描述滚出可见区。

参考图仅作为布局参考。原内容文档9.2明确三个任务构成一个主线章节，故均显示“主线任务”，不将示意图的支线/挑战类型写入正式数据。奖励、前置、目标与材料均读取原配置和运行状态。

## 可编辑场景

| 文件 | 用途 |
| --- | --- |
| `ui/main/home_view.tscn` | 主界面完整布局，与上一版首页保持一致 |
| `ui/quest/task_page.tscn` | 任务页完整布局，含静态列表与详情预览 |
| `ui/quest/task_list_item.tscn` | 任务页所属列表项模板，用于运行时动态任务 |

在Godot文件系统中双击前两个文件即可在2D编辑器查看节点排列，无需启动主菜单或创建角色。场景树内已有面板、容器、文字和按钮，不依赖运行脚本生成整页。根目录AGENTS.md的8.3节已加入本要求。

运行时main.gd实例化相同的.tscn；home_view.gd只更新文字、进度和信号，不再重建布局。task_page.gd只绑定真实数据、生成动态列表与更新详情。预览中的任务状态仅为静态显示，不会接取任务或修改存档。

可调整位置：

- 首页：`Layout/MainColumn` 的区域间距；`MainContent` 左右子节点的Size Flags Stretch Ratio；卡片StyleBoxFlat内边距、GridContainer列数/间距及按钮最小尺寸。
- 任务：`Margin` 的安全边距；`Column/Content` 的separation；`TaskListPanel`与`TaskDetailPanel`的Stretch Ratio；`Details`的间距及`ActionBar`排列。
- 动态列表项：修改task_list_item.tscn的高度、字体、内边距和默认底色。TaskPage检查器中的task_item_scene指向该模板，selected_color控制选中底色。
- 保留脚本使用的具名节点（如TaskTitle、Description、Primary）及首页导航按钮destination元数据。修改布局尺寸和容器参数不影响绑定；重命名或删除绑定节点须同步调整脚本。
- task_page.tscn里的三条静态任务用于离线预览；运行时由真实数据替换。需要统一修改动态条目时编辑task_list_item.tscn，而不是仅修改某一条预览文字。

## 行为保护

- 筛选和选中只改变页面状态，不写入世界或任务状态。
- 可接取/可提交查询复用现有QuestSystem.accept/claim，输入为一次性深拷贝；查询不会提交该副本。没有复制另一套接取/奖励业务规则。
- 正式按钮仍调用GameManager.request，经过原OperationService和QuestSystem处理。
- 公告栏隐藏未满足接取条件的委托，前置任务完成且满足其他条件后显示。任务列表从已接取的记录中筛选，支持全部、进行中和已完成。目标与材料均满足时可前往发布者交付。
- 秦守山对话只在当前所选任务目标要求对话时显示在详情操作区；人物不在同一地点或已故时禁用并提示。其他独立NPC对话仍保留在地图页面。
- “任务引导”打开原地图页，不额外推进时间、传送或增加进度。
- 接取/提交刷新后保留分类和选中任务；筛选结果为空时显示空状态。
- 原gameplay/quest/quest_system.gd、任务JSON、存档系统与格式均未修改。
