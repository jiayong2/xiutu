# 共用商店页面重构与验收

日期：2026-11-05。实现与已执行检查：PASS；最终视觉审核：待用户审核。

## 完成内容与文件

`ui/shop/shop_page.tscn`为所有现有商店共用的可编辑场景，可直接在Godot 2D编辑器预览。顶部商店名称、灵石、返回地点，第二行购买/出售；主体扣除32px外边距和16px面板间距后按15:50:35分配分类、列表、详情。纯色矩形及单线边框，商品行统一64px，无逐行交易按钮；图标为原生ColorRect占位。

`ui/shop/shop_page.gd`只绑定真实商品、分类、选中状态、详情与请求。分类来自当前模式商品的type字段，不套用示意图不存在的分类；购买显示库存商品，出售显示背包及独立装备实例。列表和详情正文分别滚动，数量、总价和确认按钮固定底部。

`ui/main/main.gd`改为加载共用场景；各商店分别保留模式、分类、选择和数量。返回回到原地点场景。灰狼牙确认弹窗沿用原流程，并显示实际出售数量，普通商品不再误标任务材料。

## 业务保护

`gameplay/shop/shop_system.gd`的 unit_price 供列表、报价和成交共用。自 2026-11-08 起，`core/operation_service.gd`的只读 trade_quote 直接复用成交校验，查询当前数量是否合法，并以相同校验查找最大数量。UI 无需复制库存、钱包、商人资金、任务前置、已学秘籍或装备出售校验。

预览查询中的confirmed=true仅用于计算灰狼牙可售数量；正式出售请求不带该字段，仍弹原确认框，取消不改变数据。已装备物品、商人离开/死亡、资金不足、秘籍已学或尚未解锁均沿原接口拒绝。原系统没有额外绑定物品字段，本轮未虚构绑定机制或改变规则。

实际交易继续调用 buy/sell/sell_equipment，按原有规则提交库存、动态价格对应的款项和 NPC 财富。报价只读取当前状态，UI 总价为服务报价单价乘当前数量，交易时由原服务重新核算。

## 2026-11-08 响应延迟复验

原先每次选择商品都会重建列表，并为各行反复还原世界状态、模拟成交以计算最大数量。交易页现在以单价建立列表，选中时更新两行高亮和现有详情面板，完整报价按选中项计算并缓存。重新绑定数据、切换购买与出售模式或筛选时重新建立列表和报价缓存。背包也改为复用物品格更新选中与详情。店铺首页绑定复用导航时取得的快照。

Godot 4.5 Mono 无界面采样各 9 次，青岚杂货铺的中位耗时为交易入口至下一处理帧 261.75 → 6.69 毫秒，首次点选回灵散的回调 255.31 → 0.17 毫秒，单次完整交易报价 27.55 → 0.028 毫秒。31 行出售列表与 91 格背包各切换 100 次，列表节点全部保留。商店交易、商店首页及背包预览脚本的无界面检查合计 97 项通过，另通过边界及气运回归。以上数据记录脚本和处理帧，实际呈现帧与长期内存曲线待图形模式验证。
