# 《仙途》V0.1 最小可玩版本：商业游戏内容设计与开发实施文档

> 文档性质：《仙途》设计基线的配套执行文档（内容清单 + 数值基线 + 垂直切片 + 制作任务 + 验收）  
> 引擎：Godot 4.x / GDScript；平台：Windows PC；UI：1920×1080 / 16:9  
> 日期：2026-11-04；状态：**可启动制作的原型提案，新增数值待试玩验收**  
> 版本标识：Content V0.1；设计依据：[现有总设计](仙途开发文档.md)及[已批准决策](decisions.md)

## 0. 文档优先级、开发目标和边界

### 0.1 原规范继承，不擅自覆盖

本文件原型基线继承以下原则：单机、行为驱动世界时间、速度排序回合制、功法=被动、法术=主动、法宝=装备加成；最多装备 10 门功法；灵根为金/木/水/火/土/风/雷/冰；UI 三面板+九宫格；数据驱动；统一操作提交、存档、Debug 与自动测试。未冻结的数值为**供原型测试的暂定值**。已批准决策优先于旧基线描述，尤其是现行在线时间、地点首页和任务流程。现行数据读取项目配置，新增正式机制或数值变更须经用户批准。

### 0.2 不是一次制作整部游戏

- **VS0（第一块垂直切片）**：1 个城镇（青岚镇）、1 个探索区（青岚山外围）、1 个洞府、3 个可对话 NPC、4 种妖兽、3 个任务、4 门功法、5 个法术、4 种可采药草、2 个丹方、1 家商店；体验 30–60 分钟。
- **MVP1**：增加云溪城、更多 NPC/怪物/商品/任务、基础自主成长与经济变化、炼气九层至筑基的完整成长和稳定性测试。
- **正式商业发行版**：待 MVP1 验证后另行规划内容量、体验时长、销量目标、美术、音效、引导、本地化与发布流程。**通过 VS0 不代表达到商业发行质量**。

### 0.3 核心体验承诺

玩家应在 3 分钟内知道下一步，在 10 分钟内完成首次战斗，在 20 分钟内感受到“战斗→资源→成长”，在 30–60 分钟内完成“采药→炼丹→修炼→突破”的首次闭环。这里是**设计目标**，不是已经验证的事实。

### 0.4 最小商业质量标准

无阻断 Bug、操作有反馈、资源可追溯、不依赖 Debug 完成游戏、可中途保存与恢复、文字与数值自洽、稳定帧率、失败有补救、玩家不会因早期资源误操作永久卡关。原型先用纯色方框和文字，**不因缺少立绘而推迟机制验收**。

### 1.2 新手灵根暂定效果

## 2. 修炼成长与第一版数值

识海和神魂按 DEC-035 纳入原根基成长。与拍卖神识威慑有关的默认值、NPC 补齐规则和公式见 [拍卖和神识专项](auction_review.md#识海神魂和威慑)。

### 2.1 炼气九层修为表（每层独立修为）

| 当前层 | 升到下一层所需修为 | 升级后新增 HP / MP / 攻 / 防 / 速 |
|---|---:|---|
| 炼气一层 | 100 | +12 / +5 / +2 / +1 / +1 |
| 炼气二层 | 150 | +12 / +5 / +2 / +1 / +1 |
| 炼气三层 | 220 | +14 / +6 / +2 / +1 / +1 |
| 炼气四层 | 300 | +14 / +6 / +3 / +1 / +1 |
| 炼气五层 | 400 | +16 / +7 / +3 / +2 / +1 |
| 炼气六层 | 520 | +16 / +7 / +3 / +2 / +1 |
| 炼气七层 | 650 | +18 / +8 / +4 / +2 / +1 |
| 炼气八层 | 800 | +18 / +8 / +4 / +2 / +1 |
| 炼气九层 | 筑基前置：1000 + 筑基丹×1 | 筑基成功单独结算 |

规则：一至八层修为满后点「晋升」确定成功，耗时 1 天、不消耗额外材料；九层修为满才能尝试筑基。晋升时溢出修为保留，但最多抵扣下一层需求；不得跳过多层而不结算。属性增长是原始属性增量，装备与功法最后统一计算。

### 2.2 修炼行为

| 行为 | 时间 | 修为基值 | 可用条件 |
|---|---:|---:|---|
| 打坐 | 1 日 | +20 | 任何安全地点 |
| 闭关 | 3 日 | +60 | 洞府修炼室 |
| 闭关 | 10 日 | +200 | 洞府修炼室 |
| 服用聚气丹 | 0 日 | +40 | 炼气期，且每日最多 1 颗 |

最终修为按 `floor(基值 × 功法倍率 × 灵根倍率 × 环境倍率 × 状态倍率)`，但最少得 1；功法同类百分比先相加，再形成一个倍率；单次最终倍率夹在 0.5–3.0。洞府 Lv1 修炼室环境倍率 1.10；其他安全地点 1.00。服用聚气丹的 +40 为直接修为，不再乘修炼倍率，防止重复叠乘。**打坐及闭关仅推进时间，不恢复 HP/MP；恢复需客栈或药品**，避免结算歧义。

### 2.3 筑基（MVP1 完整实现，VS0 只做可展示的远期目标）

筑基前置：炼气九层修为 1000、筑基丹×1、洞府或指定安全地点、没有不可突破状态；耗时 10 日；成功率基准 80%，失败消耗筑基丹、修为损失 200（不低于 0），不得降层；成功获得筑基一层、寿元上限 150、HP +100、MP +60、攻 +20、防 +12、速 +5。失败不额外扣除生命。随机结果必须记录随机流和操作 ID。以上均为可调整的原型数值。

体修、温养与功法门槛按 [DEC-031](decisions.md#dec-031--2026-11-06法体双修与温养首版)。九阶突破与现有材料表按 DEC-032 的 [V3.1 迁移记录](spirit_flow_v3_1_review.md)。

## 3. 功法数据（被动，不等同法术）

品质暂分凡品、黄阶、玄阶、地阶、天阶；VS0 仅凡品、黄阶。功法最多 10 槽，测试版开局开放 3 槽，随境界逐步开放，其余槽位显示条件；无主修/辅修。每门独立等级，Lv1–3；一门功法既可学习又可装备，学习与装备是两个不同操作。

| ID | 功法名 | 品质 | Lv1效果 | 每升1级追加 | 获取方式/标价 |
|---|---|---|---|---|---|
| `technique_qi_flow` | 引气诀 | 凡品 | 修炼效率 +10% | +5% | 初始自带；商店 60 灵石（已学不可重复购买） |
| `technique_iron_body` | 铁骨功 | 凡品 | 最大 HP +20、 防御 +2 | HP +10、防 +1 | 秦守山任务奖励或 120 灵石 |
| `technique_green_wood` | 青木长生诀 | 黄阶 | 最大 HP +30，修炼效率 +5% | HP +15、修炼 +3% | 云溪城 220 灵石（MVP1） |
| `technique_fire_breath` | 赤炎吐纳诀 | 黄阶 | 火系伤害 +15%，攻击 +2 | 火伤 +5%、攻 +1 | 青岚镇藏经商人 180 灵石（VS0 任务后解锁） |

升级消耗：凡品 Lv1→2：80 灵石+修为 40；Lv2→3：160 灵石+修为 80；黄阶分别 150 灵石+修为 60、300 灵石+修为 120。升级扣修为，但不得使角色层级倒退。装备与卸下不消耗时间，属性即时重算。**同名功法不可叠加装备**；重复秘籍应显示不可学习或允许出售，不能生成第二份可叠加被动。

掉落结果由 `RandomService` 的战利品随机流产生，同一战斗结算不得重复领取。掉落的商品售价见第 5 章。首次「猎狼委托」要求击败 1 只野狼，因牙齿必掉，不会因随机数卡住主线。

### 7.3 伤害、回合和状态

- 直接伤害（普攻、法术及敌方攻击）采用 [DEC-034](decisions.md#dec-034--2026-11-06八系法术试学与统一布局) 的有效防御减伤公式。持续伤害、引爆和固定反震各按效果规则结算。
- 普通攻击倍率 1.0；默认必中，VS0 暂不引入闪避或命中；暴击由统一随机流判定。
- 对应灵根施放同元素法术，属性倍率 1.10，否则 1.00；VS0 怪物属性抗性为 0，不做复杂相克。
- 护体：临时防御 +6（按效果配置）；灼烧：目标每次自身行动**结束时**扣 5 HP，持续 2 次该行动；潮湿：仅显示状态，VS0 不额外加伤，避免规则不明；回春术直接回复。
- 同类灼烧不叠层，重新命中刷新为 2 次；护体重新施放刷新持续次数；效果持续次数在目标行动结束时统一扣减，避免重复扣回合。
- **双方每轮按速度排序**；速度相同时玩家先行动，再按固定参战 ID；每个存活单位每轮最多行动一次；速度变化下一轮生效。
- 按 DEC-036，开战及进入新一轮时，排在玩家前面的怪物先行动，随后开放玩家指令。
- 允许普攻、法术、防御、使用物品、逃跑；防御使本次承受的最终伤害乘 0.5（向下取整、最低 1），持续至自己的下次行动开始。
- 逃跑成功率 VS0 固定 70%，成功无战利品；失败消耗当次行动。战斗中使用物品消耗行动，非战斗使用不推进时间。
- 每场战斗**结束后**统一推进 2 游戏小时；不逐回合推进世界日历。
- 战败：生命恢复至上限 30%（向上取整）、灵力恢复至上限 30%、扣当前灵石的 10%（向下取整）、回青岚镇；不会永久死亡；不颁发奖励。若掉落灵石不足，不发生负值。

> 平衡警告：表中战斗公式和敌人数值属于第一轮测试基线，须用自动模拟验证普通野狼胜率/战斗轮数，不能直接当作已平衡的数值。

### 11.5 防止 AI 编码常见问题的硬约束

1. UI 只发送请求，不能 `player.spirit_stones += 100`。
2. 静态商品配置不能作为商店运行库存，运行库存放存档。
3. 物品类型 ID 与装备实例 ID 不能混用。
4. 战斗中临时状态不直接持久化为角色永久属性。
5. 任务奖励提交与状态完成必须同一操作结算。
6. 随机事件不得直接调用全局随机函数，应使用统一 `RandomService`。
7. 固定种子 + 固定初始状态 + 固定操作序列，应得到相同结果。
8. UI 重入（连点按钮）不得重复扣款或重复产出。
9. 存档读取后必须恢复灵田定时、任务进度、商店库存、随机状态。
10. 配置缺失/ID 引用错误应在启动时给出明确错误，不得静默生成空物品。

## 14. 数值经济自检（本版专门关注软锁与套利）

1. 起始 120 灵石；任务 001 奖励 +30；一份回灵散成本 18，确保可买补给。
2. 任务 002 强制首次野狼，狼牙 100% 掉落；任务不用赌稀有战利品。
3. **种田→售卖青灵草**：每田成本 6，成熟 3 日，收获 3 株售出 21，净收益 15；这是合法的时间收益，不是瞬时无限套利。若后续增加时间无成本的“批量跳日”，需评估经济通胀。
4. **买草→炼聚气丹→卖丹**：2×15+10=40，最终卖价 35，不构成正收益套利。
5. 种田草药→炼丹→出售丹药，允许合理利润补偿时间；需要限定设施产能及时间。
6. 修炼与服丹产生修为；不能通过反复点击一个已完成炼丹/修炼结果获得重复收益。
7. **最终原型基线**：`pill_qi_gathering` 买价 90、卖价 35；若以后改变售价，必须重跑经济套利测试。

## 15. 内容制作与商业规范检查表

### 15.1 内容资产规范

每个可见内容至少拥有：稳定 ID、中文名、类型、来源、用途、描述、图标占位、是否可售、价格或奖励规则、所属版本、QA 状态；怪物额外需要战斗属性、行为 ID、掉落表、出现地点、挑战建议；任务额外需要前置、目标、奖励、失败/恢复规则；商店额外需要库存和补货规则。所有中文文案应统一命名，不在各 UI 自写不同别名。

### 15.2 美术与音效上线顺序

先纯色框与文字 → 后统一 UI icon → 再补 NPC 肖像/怪物剪影 → 最后补法术效果、交互反馈与音乐。游戏素材应有合法来源和授权记录，禁止在不明确版权的情况下直接把网络图用于商业发行。VS0 为原型，临时美术必须可替换。

### 15.3 可用性与可维护性

全部按钮支持不可用原因；价格、损失、概率、冷却时间可见；文本记录易于查错；世界时间推进时有结算摘要；取消危险操作不产生副作用；所有表中关键数据能通过 Debug 读取；跨版本修改 ID 要写迁移映射。

### 15.4 商业前置验证

保留试玩反馈表：是否在 3 分钟内知道目标、能否独立打赢野狼、是否理解功法和法术区别、是否体验到“灵田随世界时间成熟”、是否能理解任务奖励与修炼关系、是否遇到卡关、总试玩时长及主要退出原因。以真实试玩结果决定是否增添内容，而非先堆大量商品和怪物。
