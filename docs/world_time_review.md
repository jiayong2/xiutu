# 世界时间与修炼优化：已确认范围验收（2026-11-05）

## 已确认规则及范围

用户明确说明参考方案不用全部照搬、需要取舍时由用户决定。本轮先检查现有 TimeSystem、修炼/突破、月度 NPC/经济、任务、宗门、存档及页面刷新；提出文件/依赖范围后，用户确认：

1. 自动流逝 + 保留原探索/旅行/炼丹/突破等行动耗时；现实 1 秒 = 游戏 60 秒。
2. 自然每日 10、打坐 20、闭关 40 基础修为，乘原有有效加成。
3. 闭关修为封顶后继续推进选定时间；旧存档已有溢出不直接删掉，仍手动突破。
4. 手动暂停只停自动时间，主动选择的耗时操作仍能结算。

本轮实现“在线自动时间/吐纳、暂停保护、统一分段结算、按时长及目标闭关、真实变化报告”，不创建新的 NPC 关系、宗门经济、限时任务、袭击或重大事件内容。原 30 日一月、360 日一年保持，不套用示例中的新境界数值。已读 AGENTS.md、现有中文设计/内容文档、data_schema、development_plan、decisions；指定英文 game_design/content_v0_1/combat_balance 文档仍缺失。

## 实现与入口

- `TimeSystem` 继续唯一写世界日期，保留 `hours`，增加可选 `time_seconds`（不足一小时的秒数）。统一提供日历与分钟显示，首页/地图/店铺/客栈共用；没有第二套世界日期。
- `GameManager` 仅累计在线实际 delta，每完整现实秒按配置提交游戏秒数。主菜单、创建/读档、设置、战斗及其结算、NPC 弹窗、确认窗口、闭关/炼丹决策界面暂停自然时间。退出/读档不读取系统日历，不计算离线收益。
- 首页顶部暂停按钮及空格控制手动暂停；5 分钟无操作自动暂停，可在设置关闭。输入恢复自动暂停，并避免恢复的空格又立即触发手动暂停。暂停状态和倍率可见。
- 首页显示实际修炼效率、自然吐纳每游戏小时收益、进度及瓶颈/暂停/寿元提示。自动计时使用独立通知，原地刷新，不按秒重建整个页面；月度更新才刷新受影响的 NPC/商店/任务列表，保留页面选择。
- `CultivationSystem.accrue` 用整数余数累计时间收益，不能每 tick 最少加 1。自然、打坐、闭关共用公式；打坐或闭关期间不再叠加一份自然收益。原八系修炼倍率同为 1，未编造资质/体质/状态加成。
- 时间区间只在跨月时分段，月界后继续使用真实维护后的效率。聚灵阵维护费不足关闭后，后续闭关不再沿用开始时的加成。NPC 成长、突破、迁移、寿元与库存、价格继续原月度规则，随机调用顺序不变。
- 随时间获得的修为在当前境界需求处封顶，满后不存新的有效修为/小数；已有溢出保留。未调整丹药直接修为、功法升级和原突破消耗规则。筑基以上尚无成长配置时不编造下一境界收益。
- 原年月日闭关入口保留，并增加“修炼至当前境界圆满”。时长模式按用户选择完整推进；目标模式求精确达标秒数后出关，遇月界维护仍按同一模拟规则求解。
- 到达寿元边界停止继续推进；目标未达成会明确中止。沿用“寿元已尽后不可继续玩法”的已有规则；长闭关预览会警告寿元与按当前真实推演将失败的已接任务，提交前要求确认，取消不改变状态。
- 闭关提交禁重复点击，并向原事务传稳定请求 ID。结果报告按修炼、NPC、宗门、经济、世界、任务分类，全部取自真实状态差异及任务刷新结果；查看、关闭不会再次结算。报告是同一可编辑 `.tscn` 原生模板。

## 配置及存档

新增唯一新时间配置 `data/balance/time_rules.json`：倍率 60、无操作 300 秒、自然/打坐/闭关 10/20/40；由 ContentCatalog 加载并校验。原 rules.practice_day 作为历史兼容字段保留，新模式读取 time_rules 对应日收益，不维护两套运行时修为。

新增可选状态 `time_seconds`、`cultivation_fraction`、`time_paused`、`idle_pause_enabled` 和 `retreat_report`；秒余数和修为余数随存档保存。旧档缺字段按零余数/未手动暂停/默认闲置保护读取，已有整数日期和修为不改写。报告、开关及余数做结构校验；无效档不替换当前状态。外层存档版本、随机状态格式及备份机制不变。

在线真实秒缓冲只代表当前尚未提交的 tick，不从现实日期补偿；读档重置该缓冲。有效游戏时间以已提交的统一时钟状态为准。自然 tick 不向操作防重表每秒添加一条记录，避免长期积累无意义请求。
